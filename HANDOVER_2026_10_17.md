# HANDOVER — 2026-10-17 (start here as a new coder)

## 1. What this is
**RadioAI Studio Pro v2.0** is 24/7 radio automation software for KISS FM 91.5 / FCP Radio, Jaipur. It is modelled on Jazler SOHO and runs on a single Windows PC with a single operator. It handles songs, jingles, sweepers, spots (ads), SOTG (Spot-on-the-Go), clocks, a weekly grid, Rotation AI, the "Coming Up Next" tease (Stitcher), Final Log, reports, backup and restore.

## 2. Stack and how to run
- Python 3.14, **PyQt6 with native widgets only.** No HTML, WebView, Flask or JS.
- Audio: **BASS via pybass3.** The evaluation DLL is for development only; a commercial licence is needed before going on air.
- Database: SQLite in WAL mode. Schema is `database/schema.sql` (non-destructive). All SQL lives in `core/database.py` (a thread-local connection singleton).
- Run: `py main.py` (`--debug` for verbose logging). Tests: `py -m pytest <file> -q`, **one file per run.** Running several BASS files in one process can segfault at teardown, a known flake.
- Build: `py -m PyInstaller RadioAIStudioPro.spec --clean --noconfirm`, then `"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" RadioAI_Setup.iss` → `installer\RadioAI_Studio_Pro_Setup_v2.0.0.exe` (about 32.7 MB; **a smaller file means the build was truncated**).
- Repo: github.com/kundansharma903-code/radioai-studio-pro, branch **`native-pyqt6`**.

## 5. Invariants: never break these
1. `route_via_mixer=False`. The BASSmix route was rolled back in May.
2. The `_has_pending_dispatch()` gate is checked at all 3 fade triggers: `_on_engine_mix_point_reached`, `_maybe_trigger_fade_out` and `_dispatch_crossfade_overlap`. It stops music from fading over a pending spot or SOTG.
3. `_suppress_queue_emit` is set while `peek_next` runs, which stops a `queue_changed` signal storm.
4. `_is_non_music_deck_item()`: jingles, sweepers, IDs and spots play to their end, with no crossfade.
5. Never call Qt or the DB from a BASS callback or a worker thread. Emit a signal and handle it on the main thread.
6. Destructive SQL: use exact `WHERE id IN (...)`, run a `SELECT COUNT(*)` first, wrap it in a transaction, and get the operator's OK. **Never use LIKE for cleanup** (there was a real incident on 2026-05-04).

## 6. Environment traps
- Claude runs inside an MSIX container, so `%LOCALAPPDATA%` is **virtualized**.
- The real DB is `\\localhost\c$\Users\hp\AppData\Local\RadioAI Studio Pro\Database\radioai.db`, and logs are in `...\RadioAI Studio Pro\Logs\`. Read them through the UNC path. The old `...\RadioAI\radioai.db` is a stale May copy.
- Don't run DB-writing app processes from a Claude shell against the live DB. Never kill the operator's running app.
- Tests use a live-DB shield: conftest redirects the session to a temporary copy of the DB.
