## Time-Slot Freshness algorithm (operator-locked)

This is the operator's brainchild — fully captured in
`core/rotation_ai_engine.py:compute_weight()`. Reproduced
here for next-session reference.

### Weight curve

For each candidate song at hour H of a clock with primary
category C:

```
slot_age_days = days since this song last played in hour H
                (across all weekdays per operator's D2 = b)

base_weight = lookup(slot_age_days):
    today      (0d)   → 0.00   HARD VETO
    yesterday  (1d)   → 0.05   heavy penalty
    2 days            → 0.30
    3 days            → 0.60
    4 days            → 0.90
    5–6 days          → 1.00
    7+ days           → 1.00
    never played here → 1.30   BOOST

primary_boost = 1.20  if song.category_id == C
              = 1.00  otherwise (sister category)
final_weight  = base_weight × primary_boost

vetoes (final_weight → 0):
    overall_age_hr < 4              4-hour same-song rule
    overall_age_hr < 1 AND artist   1-hour same-artist rule
```

Pick = `random.choices(eligible, weights, k=1)[0]` where
eligible = `weight > 0` candidates.

### Sister pooling

Pool for primary category C = `{C} ∪ sister_categories(C)`.
Symmetric — when category B is in the same group as C, B's
songs are eligible for C's clock AND vice versa. Resolved at
query time via `db.get_sister_pool_for_category(c)`.
