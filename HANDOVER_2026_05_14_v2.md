## SOTG dispatch architecture (Phase 1 — broadcast wiring)

This is the most important new piece to understand. The Studio class
now watches `sotg_assignments` and fires drops on-air.

### Constants (on Studio class)

- `_SOTG_TICK_MS = 5000` — poll interval (5 seconds)
- `_SOTG_FIRE_TOLERANCE_S = 30` — fire if within ±30s of sharp time
- `_SOTG_MISS_THRESHOLD_S = 60` — stamp MISSED past this
- `_SOTG_HIGH_FADE_MS = 10000` — 10s fade-out for HIGH priority

### State

- `_pending_sotg_assignment: Optional[dict]` — cached drop waiting for
  song EOS (or paid spot EOS). Mirrors `_pending_spot_campaign_id`.
- `_pre_sotg_song_id: Optional[int]` — anchor for post-SOTG queue
  resume. Mirrors `_pre_spot_song_id`.
- `_sotg_active_aid: Optional[int]` — assignment id of the SOTG file
  currently on the deck.

### Tick (`_sotg_check_tick`)

Every 5s:
1. `db.get_sotg_assignments_for_date(today, status="READY")`
2. For each row, compute `delta_s = (sharp_min − now_min) * 60 − now_sec`.
3. If `|delta_s| ≤ 30` → call `_do_sotg_fire(row)` and break.
4. If `delta_s < −60` → call `db.mark_sotg_assignment_missed(aid)`.

Wrapped in try/except so a DB hiccup never kills the broadcast loop.

### Fire (`_do_sotg_fire`)

Priority router:

| Current playback | Drop priority | Behaviour |
|---|---|---|
| Paid spot on air | any | Defer (`_pending_sotg_assignment`). Paid spot always wins. |
| Song on air | LOW | Defer until song EOS. |
| Song on air | HIGH | Fade outgoing channel over 10s, load SOTG on fresh channel, mark `_fading_cid` for tail cleanup. |
| Deck idle | any | Immediate `_play_sotg_file`. |

### `_play_sotg_file`

Load + set_volume + play. Stamps `status = FIRED` + `fired_at` in DB
+ adds a `broadcast_log` row. Bypasses the priority router (used by
the defer-then-fire paths so they don't re-defer themselves).

Sets `_playback_kind = "sotg"`. Creates a synthetic `_current_track`
dict with id offset by 10_000_000 so it can't collide with `songs.id`.

### EOS handler integration

`_on_engine_playback_ended(channel_id)` now has five branches in
order:

1. **Crossfade tail** — if `_fading_cid == channel_id`, silent cleanup
   + return.
2. **Spot resume** (kind == "spot"):
   - Check pending SOTG first (paid-spot-then-SOTG chain). If set,
     fire it with anchor preserved.
   - Else compute next song from queue.
3. **SOTG resume** (kind == "sotg"):
   - NEW branch. Anchor = `_pre_sotg_song_id`. Compute next song.
4. **Stop-next** (existing).
5. **Loop** (existing).
6. **Song auto-advance** (kind == "deck"):
   - Check pending spot first.
   - **Then check pending SOTG** — fires before `_compute_next_song`.
   - Else compute next song from queue.

### Crossfade hook

`_dispatch_crossfade_overlap` now checks pending paid spot OR
pending SOTG at the TOP, BEFORE picking the next song. Without this
hook, with Studio Settings crossfade enabled, the outgoing song's
natural EOS gets absorbed by the crossfade-tail branch and pending
drops never fire — the operator-reported LOW-priority-never-played
bug. Fix: fire pending drop instead of loading next song; mark
outgoing channel as fading-tail for silent cleanup.

### Past-time guard

Server-side in `db.upsert_sotg_assignment`. When `scheduled_date ==
today` and `sharp_time < now`, raises `ValueError("Cannot schedule
… for today — that time has already passed …")`. `allow_past=True`
bypasses (used by the engine to log MISSED stamps with a sharp_time
that has slipped past).

Client-side mirror in `_SharpTimeInput.set_validate_against_today(True)`:
red border + Save button disabled when current input is past for
today's scope.
