## Established conventions (discipline rules — follow without being told)

### Communication style

- **Hindi-English mix** is fine and preferred for operator-facing
  summaries
- **Plain Hindi** required for verification questions to operator
  (broadcast-language, not coder-language)
- **Senior-dev pushback ON** — surface contradictions between prompt
  and source code before editing
- **Investigation-first** — read 3-4 files, post 4-line summary,
  wait for confirmation BEFORE editing. This was applied 100% of the
  time this session — operator never complained about it being
  excessive.
- **Trust-but-verify** — source code wins over docs/prompts
- **Brief responses** — narrate intent in 1-2 sentences before tool
  calls; long planning prose annoys operator
- **End-of-turn summary:** one or two sentences. What changed and
  what's next. Nothing else.

### Coding style

- **Cache QGradient/QColor/QFont in `__init__`** (performance invariant)
- **Partial repaints via `self.update(QRect)`** not bare `self.update()`
- **NO db calls in paintEvent**, NO `self.update()` inside paintEvent
- **Drop shadows via `QGraphicsDropShadowEffect`** (one effect per
  widget — Qt limitation)
- **Engine signals throttled** — position ≤4Hz, level meters ≤30Hz
- **Try/except every scheduler `_on_tick` path** — broadcast safety
- **`hasattr(scheduler, "signal_name")` defensive guards** when
  adding new scheduler signals — backward compat with mocks
- **Settings is a singleton** — `Settings().station_display` from
  any module
- **Inter font family is "Inter Variable"** (not "Inter")
- **PDF generators must `del writer` + `gc.collect()`** before
  returning — Windows / Edge race the file handle
- **Use `os.startfile()` on Windows** for opening files — never
  races freshly-written files
- **(NEW) When adding new paint primitives:** verify imports
  reach the `QtGui` import tuple at the top of the file. `QPainterPath`
  bit us this session. Run main.py for any paint-heavy change —
  pytest with `_RecordingSignal` mocks does NOT exercise paintEvent.
- **(NEW) Self-contained screen files duplicate chrome widgets** —
  4 libraries now share `_HeaderLogo` / `_HeaderOpenStudio` /
  `_ActiveBreadcrumbChip` / `_SidebarActionButton` / etc. (Songs
  Library / Sweepers Library / Jingles Library / The Stitcher).
  Extraction to `ui/widgets/library_chrome.py` is the carry-over
  refactor — DO this before the 5th library lands.

### Test discipline

- **Live-DB fixtures use unique prefix** + `try/finally` cleanup
- **Mock pattern:** `_FakeEngine` / `_FakeScheduler` / `_FakeIJE` /
  `_FakeSweeperEngine` / `_FakeStitcher` / `_RecordingSignal`
- **Don't modify existing test files** — add to topical files or
  create new ones
- **Run focused tests after each piece** before full suite
- **Full suite must stay green** — zero regressions tolerance
- **Wall-clock-boundary flake** in
  `test_live_at_tick_refreshes_via_existing_1hz_timer` — pre-existing
  1100ms wait race. Re-run usually passes.
- **(NEW) Single-row config tables need snapshot + restore in
  fixtures** — `stitcher_config` is the canonical example. See
  `tests/test_stitcher_screen.py:cfg_snapshot` fixture pattern.
- **(NEW) Test fakes that pass file_path strings need real on-disk
  paths** — `os.path.exists(file_path)` gates several dispatch
  paths. Use `sys.executable` / `tmp_path` files / songs DB lookup.

- **One focused commit per task** — heredoc commit message format
