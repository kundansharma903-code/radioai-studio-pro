## 0. YOUR IMMEDIATE TASK (operator-approved, not yet started)

**Clock Editor — show what an AUTO clock actually contains (A + B).**

Symptom (operator screenshot): opening an AUTO clock (e.g. "AUTO ·
Pool 08") in the Clock Editor shows an **empty clock face** even though
the clock has 3 elements.

Root cause (already diagnosed — verified against the live DB copy):
- The clock DOES have slots. `clock_slots` for clock 4039 =
  `sweeper(random) → song(Pool 08, random_from_category) → jingle(random)`,
  ordered by `slot_order` 1/2/3.
- **Playback is CORRECT** — the scheduler cycles slots by `slot_order`,
  so on-air plays sweeper→song→jingle fine. This is a **display-only**
  bug; do NOT touch the scheduler.
- The `ClockFaceWidget` (`ui/widgets/clock_face.py`) draws each element
  at its `minute_position`. Auto-grid-built slots all have
  `minute_position = 0`, so `_slots_to_elements` in `ui/clock_editor.py`
  (~line 1837) passes `minute_position: 0` for all three → in
  `_rebuild_paths` (`clock_face.py` ~line 175) `start_m = float(mp)` = 0
  for every element → all three **stack at 12 o'clock** → face looks
  empty.

**A — fix the face render:** when a clock is *sequential* (all slots
`minute_position` 0/None), lay elements out one-after-another instead of
all at minute 0. Cleanest approach: in `_slots_to_elements`, if the DB
`minute_position` is 0/NULL, pass `minute_position=None` so the face's
existing `running_min` fallback chains them; keep explicit positions
when a slot genuinely has one. (Confirm no other caller depends on the
`0` behaviour.) Verify: the 3 arcs (sweeper/song/jingle) spread around
the ring.

**B — readable list:** next to / below the face, show a plain list of
what the clock plays, e.g.
```
1. Sweeper  (random)
2. Song     — Pool 08 category
3. Jingle   (random)
```
so the operator can READ the clock's contents (category name, sweeper,
jingle) without decoding the circle. Element type → label via the
existing `DB_TO_ELEMENT_TYPE` map; category name via `db.get_category`.

Constraints: **display-only, on-air-safe, no scheduler/playback change.**
Add tests (a clock-editor test file exists: `tests/test_clock_editor.py`).
Follow the workflow: 4-line summary → operator "go" → build → per-file
tests → rebuild installer → operator smoke test → commit on "commit".

## 5. HARD-WON LESSONS (do not repeat)

- **NEVER force-kill any process holding the live DB** — caused the
  07-01/02 corruptions. Graceful close only. Before ANY batch DB write:
  confirm the app is closed (`tasklist //FI "IMAGENAME eq RadioAI Studio
  Pro.exe"`), back up the DB, wrap in a transaction / `wal_checkpoint`.
- **Restore must be restart-based** — never overwrite a live/open DB.
  `backup_restore.apply_staged_restore()` runs at boot before any
  connection. Follow that pattern for any DB-swap feature.
- **Verify the tree before PyInstaller.** A `git stash` left by an
  interrupted test command shipped a build without the day's fixes on
  07-03. Always `git status` + `grep -c <marker> <file>` first.
- **MSIX virtualization trap** — Claude Code runs inside the Claude
  desktop MSIX container; its `%LOCALAPPDATA%` view is a stale LocalCache
  copy. **Read the operator's real log/DB via UNC:**
  `\\localhost\c$\Users\hp\AppData\Local\RadioAI Studio Pro\...`
  (PowerShell) or copy it out first. See `memory/env_msix_virtualization.md`.
- **broadcast_log only sees what's logged** — songs advance via two
  paths (direct + crossfade). Count on-air songs from the LOG's
  `deck play` + `crossfade started`, or the DB now that `97ef136` logs
  both.
- **Watchdog downtime ~30s**, not 90 (I misspoke once). 5s marker + 10s
  relaunch + ~14s boot.
- **All 3 invariants stay green:** `route_via_mixer=False`,
  `_has_pending_dispatch()` gate, `_suppress_queue_emit`. Break Policy
  and aircheck were deliberately built to not touch them.
- Run touched test files **per-file** (`-p no:faulthandler` gives a
  clean summary despite the BASS teardown flake).
